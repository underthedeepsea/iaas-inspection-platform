# GPU and host inspection contract

Approved scope is 17 metric families: GPU utilization, used/total memory, temperature, window Xid events, DRAM single/double bit ECC deltas; host CPU busy, available/total memory; filesystem available/size; disk read/write throughput, read/write mean latency, busy ratio. No NVLink. Every value carries quality and collected_at; missing/unsupported/reset never becomes zero. ECC includes source metric and explicit semantic and DRAM scope; corrected is not renamed SBE without source attestation.

Identity is environment + host stable ID; each GPU UUID becomes a separate GPU asset with immutable model/config in each observation. Host observations retain filesystem mount/device identity and disk IDs. Engine bindings reference exact same-environment inference asset identities and overlapping windows, include completeness; incomplete/shared ownership permits only device-level observations. Source/sample idempotency is environment scoped and conflicting reuse rejects atomically.

Formal gpu-host-health plugin shares Run, CheckResult, Finding, Risk, Evidence, reverify and AI context. GPU_POOL and HOST are active resource selections. Mixed runs freeze each supported source at creation; completed runs never recompute. One result per asset is retained; component diagnostic keys and coverage are frozen. Host risks aggregate per asset/item, and recovery requires a post-handling fresh observation with all prior failing component dimensions covered. Missing/replaced components cannot recover risk. Valid DBE failure dominates unrelated missing data. Hardware event recovery requires explicit validated source attestation with referenced prior event identifiers after disposition; zero new events alone cannot recover.

Analysis uses historical device/model/config matched baseline within 14 days, min 8 points, median/MAD and minimum effect, comparable LLM QPS, prompt/generated token throughput, running and cache features. Baseline absence is diagnostic NOT_READY and is not evidence of health. Basic complete telemetry may remain normal while advanced coverage is unavailable; recovery of previous advanced findings requires ready corresponding diagnostics. Short confirmation uses at least 2/3 comparable points; two-sided CUSUM catches gradual drift. Counter reset is an explicit quality condition and interrupts ECC growth sequences. SBE single occurrence, recurrence and acceleration are separate; new DBE is immediately critical. Xid window events are deduplicated by event identity and categorized with conservative severity; unknown code is unclassified.

Theil-Sen disk-space slopes require at least 6 chronological points and consistent short/long negative slopes; forecast is time to configured reserve, bounded to nonnegative. Host memory reports sustained decline only. Suspected correlations: busy GPU/output decrease; waiting/idle GPU; temperature higher at similar workload; host memory drawdown; IO latency drift; hardware plus service degradation. No thermal-throttling conclusion without clocks/power; no definitive device degradation without IOPS/IO size. Output identifies evidence, limitations and exact overlap.

API accepts strict JSON external snapshots and returns immutable evaluation. UI uses existing resource/run/result/risk screens plus profile diagnostics/quality/metrics. Tests cover below-threshold degradation, high load/preallocation, missing/reset, event dedupe, environments/idempotency, source mixing, immutable run evidence and guarded reverify. No production rollout, push, PR or commit in this task.
