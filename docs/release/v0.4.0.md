# v0.4.0 发布说明

v0.4.0 将 v0.3.0 后主分支已有的 GPU / 宿主机健康巡检纳入发布，补充当前 20 项推理性能指标的 Markdown 清单，并统一项目与前端版本元数据。本轮同时修复规则详情缺少具体可采集指标和判定规则的问题，页面可查看实际输入字段、指标用途与当前策略阈值。

## 相对 v0.3.0 的变化

- 正式支持 `GPU_POOL` 与 `HOST` 资源，注册 `hardware.gpu_health`、`hardware.host_health` 两条规则，使用 `gpu-host-health` 代码插件。
- 接收外部硬件聚合快照，覆盖 17 项指标字段：GPU 利用率、显存已用 / 总量、温度、窗口 Xid 事件、DRAM 单 / 双比特 ECC 增量；主机 CPU 忙碌率、内存可用 / 总量；文件系统可用 / 总量；磁盘读 / 写吞吐、读 / 写平均延迟及 IO 忙碌率。
- 硬件诊断包含条件基线、持续退化、容量趋势、硬件事件及与推理引擎的疑似关联；质量状态、基线不足及诊断限制随结果输出。缺测、不支持或计数重置不会补零。
- LLM / GPU / HOST 可在同一巡检 Run 中运行，各插件独立冻结输入，结果进入既有检查结果、证据、风险与复验流程。恢复要求相关异常组件有效覆盖；硬件事件还需明确的处置后验证证据，零新增事件不能直接代表恢复。
- 增加 [20 项推理性能指标清单](../api/inference-performance-metrics.md)，列出字段、单位、评估用途、数据约束与 API。
- 规则列表与详情 API 返回 `input_contract`、`supported_metrics`、`judgment_rules` 和 `policy_profiles`，后端根据实际 schema 和策略文件构建信息。
- 规则详情展示 LLM 20 项、GPU 7 项、HOST 10 项指标的字段、中文含义、单位与范围、输入路径及展示 / 主判定 / 辅助证据等用途。详情展示默认阈值与引擎 / 模型覆盖后的有效阈值、覆盖查找顺序、具体判定与连续确认规则，以及缺测、基线不足等未就绪边界。
- `VERSION`、`frontend/package.json` 和锁文件中项目根节点版本统一为 `0.4.0`；依赖版本保持原配置。

硬件字段、快照身份、绑定、幂等与批量导入要求见 [GPU / 宿主机巡检接入](../api/gpu-host-inspection.md)，算法和恢复约束见 [硬件巡检设计](../design/gpu-host-inspection.md)。

## 包含的既有能力

本版本保留 v0.3.0 的推理性能画像与提示词管理：`llm.performance_profile` 支持 vLLM / SGLang，评估固定阈值、14 天动态基线和默认 60 分钟趋势；提供首页、资源与 Run 的 AI 解读、代码插件目录及受管理员令牌保护的提示词编辑。

巡检以真实外部快照为输入，支持手动运行和 Airflow 内部 HTTP 编排；代码评估与 AI 解读相互独立，模型故障不能改变代码巡检事实或风险。平台不直接连接 GPU 驱动或 SSH，也不执行自动重启、迁移、改配置、扩缩容或删除。

## 升级

先记录部署提交、配置与迁移状态，备份数据库，并在 PostgreSQL 副本演练。已有数据库应保留，不运行演示 seed 或空库重建。

在使用本版本代码的 Web 环境执行：

```bash
source .venv-web/bin/activate
python manage.py migrate --plan
python manage.py migrate --noinput
python manage.py seed_launch
```

`seed_launch` 注册推理、GPU 和 HOST 正式插件，退役旧演示插件绑定。旧推理快照如尚未关联资产，按 [推理插件与提示词发布运行说明](iaas-llm-plugin-prompt-runbook.md) 先执行 `backfill_inference_assets` 的 dry-run，再核对并按需 `--apply`；已有完整关联无需重建历史数据。

设置 `DEPLOY_COMMIT_SHA` 为实际部署提交。接入硬件快照后，核对数据质量、覆盖、插件版本和手动混合 Run。恢复定时调度前验证内部 HTTP 调度参数及真实输入；GPU / HOST 可使用 `HARDWARE_SNAPSHOT`，混合输入使用 `EXTERNAL_SNAPSHOTS`。模型、提示词令牌和 Airflow 切换沿用上述运行说明。

## 验证与部署边界

既有硬件巡检范围来自已合入主分支的 GPU / 宿主机巡检实现。该实现已有核心检查通过记录；其端到端 CI 存在 5 项旧场景失败，本轮未修复这些遗留问题。CI 以对应 PR 检查为准，不能将此版本描述为全部端到端检查通过。

本轮已完成的本地验证：

- 后端新规则详情及原规则 API、策略、插件注册表、LLM 合同和硬件兼容回归：44 项通过。
- 前端规则详情交互：4 项通过；前端构建通过，仍有原有的构建体积警告。
- Django 系统检查和 diff 格式检查通过；既有版本约束测试 3 项通过。项目版本与锁文件根节点一致为 `0.4.0`，依赖未变化，文档本地链接检查通过。
- 重启本地后端后，经前端 `5174` 代理验证健康接口返回版本 `0.4.0`、数据库正常；列表与详情的指标数量一致为 20 / 7 / 10，TPOT 单位为 `ms/token`，Qwen 模型 TTFT 覆盖阈值为 warning 500 ms / critical 900 ms。前端完整测试 fixture 与实际接口 payload 一致。

真实生产采集、数据库迁移、Airflow、模型服务和吞吐验收仍需在目标部署独立执行；本发布说明不代表这些验收已完成。
