# v0.2 内部 MVP 上线候选

本轮以 2026-09-10 MVP 收敛方案替代旧平台扩张任务。正式范围是 CONTROL_PLANE、LLM_RUNTIME 与三个静态确定性规则；原平台能力保留并冻结。未接入真实生产基础设施。

## 初始化与运行

使用 Python 3.10、PostgreSQL 和 frontend/package-lock.json 锁定的前端依赖。将 .env.example 中的变量配置到进程环境（Django 不自动加载此文件）。

```sh
python manage.py migrate --noinput
python manage.py seed_launch
python manage.py check
python manage.py makemigrations --check
```

`seed_launch` 可重复运行，只启用两类资源下的三条首期规则绑定，不删除旧数据。测试环境可运行 `python manage.py seed_e2e` 创建测试账号和规则；可选 `seed_e2e_complete` 生成最近三日的首期资源演示历史。测试账号不能用作生产账号。

本地：`DJANGO_SETTINGS_MODULE=config.settings.dev`、`BACKGROUND_TASK_PROVIDER=local`。
生产：`DJANGO_SETTINGS_MODULE=config.settings.prod`、`BACKGROUND_TASK_PROVIDER=airflow`，配置 Airflow URL、认证、`AIRFLOW_MANUAL_INSPECTION_DAG_ID=iaas_manual_inspection`。

Airflow 只加载 airflow/dags 下的每日与手动批处理 DAG；配置 `INSPECTION_API_BASE_URL`、`AIRFLOW_INTERNAL_TOKEN`、每日 DAG 的 `INSPECTION_ENVIRONMENT_ID`。所有阶段调用现有 `/api/internal/v1/batch/inspection-runs/{id}/…/`，失败向 Airflow 传播并重试。在线 AI DAG 仅作为历史文件留在 docs/experimental，不要部署该目录。

## 事实与解释

- 反亲和按输入快照中的 Pod Host 放置关系判断。
- TTFT P95 用 nearest-rank，默认阈值 180ms、最少三个样本。
- Queue 最后连续三个点全部 > 10 才失败。
- 以上阈值仅用于模拟数据，不是生产 SLO。
- 每个 ItemRun × Asset 只有一个最终 CheckResult，重复投递不改写完成事实。
- FAIL 生成 Finding，风险关联要求相同资产的 FAIL 证据；风险详情保存指向 CheckResult 的 Evidence。已处理风险需同资产同规则 PASS 才能通过复验。
- UNKNOWN 不生成风险，没有 PASS/FAIL 的资源不显示健康分数。Coverage 来自实际 CheckResult。
- 新模拟数据保存当时的资产拓扑快照，新手动运行冻结各资源的资产分母及规则配置。迁移前历史记录不补造 CheckResult，页面明确显示无逐对象结果。
- `POST /api/v1/resource-types/{code}/analysis` 同步返回最终解释；旧 investigations 路由兼容同一执行方式。AI 只接收本轮范围内结果、Finding、Risk、Evidence 和上一轮同规则结果，最多 50 条检查记录，截断时明确提示。
- AI 单轮、零工具调用、Provider 传输超时不超过 30 秒。模型故障只将 Investigation 标记为失败，不修改检查和风险。

## 验收

```sh
DJANGO_SETTINGS_MODULE=config.settings.dev python -m pytest -q
cd frontend
npm ci
npm test
npm run build
npm run e2e
npm run e2e:real
```

浏览器验收前运行 `seed_e2e`，启动 Django 8000 端口，配置 `LLM_PROVIDER=fake`、`LLM_TIMEOUT_SECONDS=30`。测试 Provider 根据真实持久化检查事实生成明确标识为模拟 AI 的说明，不替代确定性规则。

基础浏览器测试使用独立端口 5176，真实端到端测试直接访问 Django 8000 端口提供的生产构建，避免误复用其他应用。需要 Playwright Chromium；也可设置 `E2E_BROWSER_EXECUTABLE_PATH` 使用本机兼容浏览器。

三条核心流程：控制面异常与风险、LLM TTFT/Queue 与覆盖率、AI 解释引用证据。另有 AI 网络失败时保留检查结果的浏览器测试，以及 Provider 异常不修改风险的后端测试。

本地验证：后端 447 项、前端 48 项、基础浏览器 2 项、真实前后端浏览器 4 项；数据库迁移检查和前端构建通过。最终 CI 状态以对应提交的 GitHub Actions `core`、`e2e` 结果为准。没有执行生产部署，也没有恢复延期的平台能力。
